# domiso

ピアノのドミソに合わせて声を出し、音程が合っているかを判定するスマホ向けの音感トレーナー。
画面を見ずに「お手本 → 歌う → 評価を聞く → 次へ」を自動で繰り返せる。

## モード

「音の並び」で、各コードの上で歌う音を ドミソ（1・3・5度）か ドレミファソ（1〜5度）から選べる。
ドレミファソはメジャーで ド・レ・ミ・ファ・ソ、マイナーで ミ と ファ の間が半音（自然的短音階）になる。
行ったり来たりは ドレミファソファミレド、ランダム順は5音を並べ替える。最初に鳴らす和音はどちらも三和音。


- **重ねる**: ピアノと一緒にドミソを歌う
- **コードチェンジ**: C → F → G → Am … とコードを変えて各コードの根音・3度・5度を歌う
- **ランダム順**: ドミソの順番を毎回シャッフル
- **補助輪フェード**: 2コード連続で全問一発合格すると手助けが1段階減り、2回続けて失敗すると戻る
  （重ねる → 先に鳴らす → 和音だけ → 根音だけ → 最初だけ）

### スライド

設定の「スライド」をオンにすると、どのモードでも「ドー」と声を切らずにドミソを一息で歌う練習になる。
キープ時間ぶん音を保つと次の音への合図が鳴り、そのまま次の音へ移る。
移ったあと最初に声が落ち着いた音程（着地）で判定するため、ずり上げ・ずり下げで合わせても「一発」にはならない。
一発で着地すると小さな高い音が鳴り、フレーズの最後に一番ずれた着地を読み上げて聞き比べさせる。

合格に必要なキープ時間は 0.5〜2 秒から選べる（既定 1 秒）。

外れたときは「低い／高い」を読み上げ、自分の音と正しい音を続けて鳴らして聞き比べさせ、1回だけ再挑戦できる。
2回続けて無音なら一時停止し、声を出すと再開する。

### チューナー

ホームの「チューナー」から、課題なしで自由に声を出して音程を見られる。
一番近い音名とずれ（セント）を表示し、音程の線が右から左へ流れる。判定の幅に入っている部分は緑になる。

### カラオケ

ホームの「カラオケ」から。声だけの音声（先生の手本の録音、アカペラなど）を選ぶと、
声のある区間を検出して半音に合わせた音程バーを作る。再生しながら、流れてくるバーと自分の声の線を重ねて表示し、
曲の最後にスコア（バーの時間のうち判定の幅に入っていた割合）、合格した音符の数、全体の高め・低めの傾向を出す。

- 音声の前後にある無音（最大音量より 60dB 以上小さい部分）は自動でカットする
- テンポを検出し、音符を拍のマス目（16分音符程度、1マス0.1〜0.2秒）に合わせる。マス目より短い揺れ・装飾音・しゃくりや、
  音から音へ移る途中の音はバーにしない。カラオケ画面には拍の線を引く
- 同じ高さの音が続いても、発音が変わる所（子音で音量がくぼむ所や、母音がはっきり変わる所）では別の音符に分け、
  ガイドメロディも鳴らし直す。ビブラートで伸ばしている音は分けない
- 録音全体が平均律から少しずれていても（A=442 など）、そのずれを推定して判定に反映する
- 流す音は「伴奏」「お手本の声」「ガイドメロディ（バーから合成）」を自由に組み合わせられる。CLI で作ったデータなら「原曲」も流せる。オクターブを上下に移せる
- ガイドメロディは音声（WAV）や MIDI ファイルとしても保存できる
- 再生速度を 0.5〜1.5倍で変えられる（音程は変わらない）。バー、ガイドメロディ、採点も速度に合わせて動く
- 解析データは `*.domiso.json` として保存でき、次回は開くだけで解析を省ける。音声なしで開くとガイド音で歌える
- 伴奏付きの曲は、下の CLI で声と伴奏に分けてから使う
- 自分の線がバーより遅れて見えるときは「遅延補正」で合わせる

### リプレイと練習プラン

- **テイク**: カラオケで歌うと、声と音程を録音して端末（IndexedDB）に残す。一覧から「リプレイ」「保存」（音声と
  `.domiso-take.json` に書き出し。あとで「ファイルを開く」で戻せる）「保存して削除」「削除」ができる
- **リプレイ**: 自分の声・お手本の声・伴奏・ガイドメロディを好きに混ぜて再生し、左右に分けて聴き比べられる。
  A-B リピートと速度変更、線をタップするとその音の「自分の声 → 正しい音」を聞き比べられる。
  ゆっくり歌ったテイクは、その速さで声を重ねる
- **苦手フレーズ**: 休みでフレーズに、長い休みでブロック（最大10フレーズ）に分け、歌った範囲のフレーズを採点する。
  声が出ていない・全体に高い/低い・ずり上げ・跳躍で外れる・伸ばしで下がる・入りが遅い、を見つけ、
  70点未満のフレーズ（少なくとも3つ、多くて5つ）を練習の対象にする
- **練習プラン（講師モード）**: 手を使わずに自動で進む。フレーズごとに「聴く（0.7倍）→ 音取り（ピアノ1音ずつ）→
  一緒に（0.75倍）→ メロディだけ → 伴奏だけ（0.85倍）→ あと少し（0.95倍）→ 本番の速さ」と、2回続けて合格するたびに
  補助を減らして速くする。2回続けて失敗すると1段階戻り、一番やさしい段階でも外れる音はピアノで音取りし直す。
  クリアしたフレーズは2つずつつなげて歌い、ブロックを通して、最後に曲全体を通す。前回クリアしたフレーズは最初におさらいする
- 練習プランは進み具合ごと端末に保存され、`.domiso-plan.json` に書き出せる（曲の解析データを含むので、
  音声ファイルと一緒に開けばそのまま練習できる。段階の速さや合格点はファイルで変えられる）

## CLI（伴奏付きの曲からカラオケデータを作る）

PC で AI によるボーカル分離（[audio-separator](https://github.com/nomadkaraoke/python-audio-separator)、
既定モデルは Mel-Band RoFormer）を行い、アプリと同じコードで音程を解析する。

```sh
pnpm cli 曲.wav                       # 声と伴奏の両方を AI で分離
pnpm cli 曲.wav --inst 曲-inst.wav    # 公式インストがあれば、位置を合わせて伴奏に使う
```

出力先（既定は `./<曲名>/`）に `<曲名>.domiso.json`、`<曲名>.vocals.m4a`、`<曲名>.inst.m4a`、
`<曲名>.original.m4a`（前後の無音だけカットした原曲）、`<曲名>.guide.m4a` と `<曲名>.guide.mid`（ガイドメロディの音声と MIDI）ができる。
テンポは元の曲（打楽器を含むので拍が取りやすい）から検出する。マス目の細かさは `--grid 16`（既定）、`--grid 8`、
`--grid off`（声のとおり）で選べる。
音声はすべて同じ時間軸にそろっている。スマホに移し、カラオケの「ファイルを開く」で .json と .m4a をまとめて選ぶ（原曲は省いてもよい）。

必要なもの: Node.js、ffmpeg、[uv](https://docs.astral.sh/uv/)。

分離に使う Python の環境（audio-separator、PyTorch など）は `cli/separator/` の uv プロジェクトで、
`pnpm cli` が `uv run` で呼ぶときに自動で用意される（初回は PyTorch などのダウンロードで数分かかる）。前もって入れておくなら:

```sh
uv sync --project cli/separator
```

Linux と Windows では CUDA 版の PyTorch を入れる（GPU がなくても動く）。別の audio-separator を使うときは `--separator <コマンド>`。
初回はモデル（数百MB）を `~/.cache/domiso/models` にダウンロードする。
RTX 5060 Ti では 3分45秒の曲が約30秒で終わる（BS-RoFormer は `--model model_bs_roformer_ep_317_sdr_12.9755.ckpt`。精度はほぼ同じで約5倍遅い）。

### 再生中の音を録音する

```sh
pnpm cli record                 # 鳴り始めを待って録音し、無音が5秒続いたら自動で止めて WAV に保存
pnpm cli record --process       # 録音後、そのまま分離・解析まで（出力は録音ファイルの隣の <曲名>/）
pnpm cli record --list          # 録音できるデバイスの一覧
pnpm cli record --device スピーカー  # 既定以外の出力デバイスを録る（名前の一部でよい）
```

前後の無音はカットして保存する（前 0.2秒・後ろ 0.5秒の余白は残す）。Ctrl+C でもその時点までを保存する。
`--silence <秒>`、`--threshold <dB>`（既定 50 = -50 dBFS）、`--max <秒>`、`-o <ファイル>` で調整できる。

- Windows（WSL を含む）: Audacity のループバックと同じく、WASAPI で出力デバイスの音を直接録る（既定の出力デバイス。
  設定は不要）。Windows 標準の PowerShell で `cli/wasapi-loopback.ps1` を動かしている。
  `--backend dshow` にすると Windows 側の `ffmpeg.exe` で DirectShow から録る（Voicemeeter や VB-Cable、ステレオ ミキサー
  など、再生音が流れ込む録音デバイスが必要。音を流しながら `--probe` で選べる）
- Linux: PulseAudio / PipeWire の既定の出力のモニター（`@DEFAULT_MONITOR@`）を録る。WSL で Linux アプリの
  音を録りたいときは `--backend pulse`

## 開発

```sh
pnpm install
pnpm dev     # https で起動（スマホのマイクには HTTPS が必要）。同じ LAN のスマホから開く
pnpm test
pnpm build
```

main に push すると GitHub Actions で GitHub Pages にデプロイされる。
